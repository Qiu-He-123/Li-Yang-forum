二、项目函数索引

后端核心函数
- get_settings()：读取并缓存配置。新增配置必须先加到 Settings。
- get_db()：FastAPI 数据库依赖。接口里通过 Depends(get_db) 获取 Session。
- hash_password(password)：bcrypt 加密密码。
- verify_password(password, password_hash)：校验密码。
- create_token(subject, minutes=None, days=None)：生成 JWT。
- decode_token(token)：解析 JWT，返回用户 id 字符串。
- current_user(access_token, db)：从 HttpOnly Cookie 读取 access_token 并返回当前用户。失败抛出 ErrorCode.NOT_LOGGED_IN / TOKEN_INVALID / USER_NOT_FOUND。
- admin_user(admin_token, db)：从 HttpOnly Cookie 读取 admin_token 并返回当前管理员（T2-1）。失败抛出 ErrorCode.NOT_LOGGED_IN。所有 /admin/* 接口必须 Depends(admin_user)。
- extract_ip(request)：从 Request 中提取客户端 IP，校验 XFF 格式（T7-13），失败 fallback 到 request.client.host。
- ok(data=None)：生成统一返回结构 {"code":0,"msg":"success","data":...}。
- get_error_message(code)：根据错误码返回具体中文消息。所有业务错误统一返回负数错误码，前端可直接展示 msg。
- pydantic_error_to_code(errors)：将 pydantic 校验错误列表的第一条映射为业务错误码（如 phone 缺失 -> -1，password 缺失 -> -3，content 缺失 -> -9）。
- setup_logger()：配置 loguru 控制台彩色输出 + logs/app.log 文件滚动日志（10MB / 7 天）。
- log_user_action(db, user_id, action, detail, ip)：用户操作审计日志，同时写 loguru 文件日志和 operation_logs 表（同事务提交）。ip 为 None 时记录 "unknown"（T7-14）。

后端业务 service 函数（T1-5 抽象后，route 仅调用 service）
- auth_service.register/login/logout/refresh/change_password：登录注册全套业务逻辑。
- post_service.list_posts/create_post/update_post/delete_post/list_drafts/list_favorites/list_likes：帖子相关业务，含 AI 审核 + 标签 + 分页 + 搜索。
- comment_service.list_comments/create_comment/delete_comment：评论业务。delete_comment 删除根评论时级联删除所有回复（T9-1 Bug 修复），重新统计 comment_count 返回绝对值。
- interaction_service.like_target/unlike_target/favorite_post/unfavorite_post/create_report：互动业务。flush 后才 +1 避免 IntegrityError count 不回滚（T3-4）。
- user_service.get_profile/update_me：个人主页业务。like_count 用 join 替代子查询（T8-4）。
- admin_service.admin_login/admin_posts/admin_comments/admin_users/admin_reports/admin_logs/admin_user_logs/create_announcement：管理员后台业务。admin_id 写入 OperationLog（T7-6）。
- notification_service.create_notification(db, user_id, title, content)：互动发生时写通知（T5-5）。
- rate_limit_service.check_rate_limit(ip)/record_login_failure(phone)/is_login_locked(phone)：IP 限流 + 登录失败锁定（T7-8/T7-9），SQLite 持久化。

后端接口函数（route 层，仅做参数校验 + 调 service）
- send_code(phone)：开发阶段验证码 stub，固定 dev_code 为 123456；生产应替换短信服务和 Redis 冷却。
- register(payload, request, response, db)：调 auth_service.register。
- login(payload, request, response, db)：调 auth_service.login。
- logout(response, db, user)：调 auth_service.logout，撤销 refresh_token（T2-5）。

- auth_me(user)：GET /auth/me，校验当前 Cookie 是否有效。
- change_password(payload, db, user)：修改密码，撤销其他设备 token。
- list_schools(db)：返回四个校区。
- list_posts(view, page, page_size, q, category, tag, db, user)：帖子流，支持 all、school、hot、latest 四种视图 + 分页 + 搜索 + 标签过滤（T4-11/T6-8）。
- create_post/update_post/delete_post：调 post_service。
- list_comments(post_id, page, page_size, db)：评论分页（T8-3）。

- admin_user_logs(user_id, action, db)：GET /admin/user-logs，查询用户操作日志。
- create_announcement(payload, db, admin)：后台创建公告，admin_id 写入日志。
- list_announcements(school_id, db)：按 school_id 过滤（T7-7）。
- list_notifications/mark_notification_read：通知列表 + 已读（T5-5）。
- websocket_endpoint(websocket)：WebSocket 基础 echo 入口。

AI 服务函数
- ai_service.check_text(content)：文本审核。业务层只能调用这个方法，不允许直接请求第三方模型。失败时返回 {pass: True, reason: "AI 不可用，已放行"} 不阻塞业务（T7-1/T8-1）。
- ai_service.check_image(image)：图片审核入口。当前直接放行（T7-2，TODO 接入视觉模型）。
- ai_service.generate_tags(content)：帖子标签生成。失败时返回 []。
- ai_service.summary(content)：举报摘要生成。失败时返回 ""。
- ai_service.get_status()：返回 AI 可用状态（available + reason），用于前端显示降级提示（T8-1）。
- ai_service.chat(prompt)：通用 AI 对话封装。
- AIService._chat(prompt)：内部 OpenAI 兼容请求实现，含超时、重试和日志。熔断器：5 分钟内失败后跳过所有 AI 调用（T8-1）。

前端关键方法
- session.validateSession()：调用 /auth/me 校验 Cookie 是否仍然有效。失败时调用 clearSession() 清理本地状态。
- session.clearSession()：清除 localStorage.userId / nickname 和内存中的 session 状态。
- session.login(payload)：调用 /auth/login 并保存 userId 到 localStorage。
- session.logout()：调用 /auth/logout 后端清除 Cookie，再清理本地状态。
- school.loadSchools()：加载校区。失败时返回空数组 + ElMessage.error（T7-4，不再 fallback 假数据）。
- post.loadPosts()：按当前视图 + 分页加载帖子流。
- post.setPage(p)：切换页码后调 loadPosts()。
- user.loadProfile()：加载当前用户个人主页统计。
- interaction.loadAll()：加载 likedPostIds / favoritedPostIds / likedCommentIds 集合，用于 active 态回填（T4-6）。
- PostEditor.publish(asDraft)：发布帖子或保存草稿。T9-1 修复：发布后 postStore.setPage(1) + emit('published')。
- CommunityHome.onPostPublished()：T9-1 修复：发布后 postStore.setPage(1) + loadPosts() + 滚动到顶部。
- PostCard 点赞/收藏/举报：根据 active 态调 POST 或 DELETE（T4-6）。
- CommentList.submit/submitReply：发表评论或回复，用后端返回的 post_comment_count 绝对值覆盖（T6-6）。
- CommentList.onCountUpdated(total)：T9-1 修复：转发后端返回的绝对评论数，替代之前的 count-changed(delta) 手动加减。
- CommentItem.onDelete()：T9-1 修复：用后端返回的 post_comment_count 绝对值 emit('count-updated')。
- http.ts 拦截器：code === -101 时自动调 /auth/refresh 续期（T2-7），失败清 session + 跳首页。

三、特别注意容易误解的思路部分

1. 项目名称
页面标题是"立洋校园社区"，Logo 副文案是"LY Community"。不要改回"立洋社交"，校园社区这个名字更适合后续扩展。

2. 校区不是普通标签
用户注册必须选择校区。帖子有所属校区。首页四个切换里，"本校区"必须基于当前用户 school_id 过滤，不是前端随便筛标签。

3. 所有接口保持统一返回格式
后端接口应返回：
{"code":0,"msg":"success","data":{}}
参数错误等业务错误不要让前端收到不一致结构。当前 main.py 已把 HTTPException 和参数校验错误映射为统一结构。

3.5. 错误码必须返回具体原因，不要笼统说"参数错误"
所有业务错误统一返回负数错误码，前端按 code 决定 UI 行为，msg 直接展示给用户。
- 错误码常量定义在 app/core/errors.py 的 ErrorCode 类中，分四组：参数校验 (-1 ~ -15)、鉴权 (-100 ~ -104)、业务冲突 (-200 ~ -210)、权限 (-300)、兜底 (-1000 / -9999)。
- get_error_message(code) 把错误码翻译成中文消息，如 -1 -> "手机号未填写"，-9 -> "内容不能为空"。
- pydantic 校验错误通过 pydantic_error_to_code() 映射成具体错误码（依据 loc 的字段名 + type 判断缺失/格式/长度）。
- 业务接口里抛 HTTPException 时 detail 必须传 ErrorCode 常量（int），不要传字符串。例外：AI 审核返回的动态原因仍是字符串。
- 新增字段或新接口时，对应错误码要加到 ErrorCode 和 _ERROR_MESSAGES 里，前端 http.ts 拦截器会自动抛出带 msg 的 Error，ElMessage 直接展示。
- 严禁改回笼统的 "参数错误" / code=1。如果用户看到 "参数错误" 一定是没给具体错误码，是 bug。

3.6. 登录态持久化必须用 Cookie max_age
登录后写 Cookie 必须显式设置 max_age，否则是 session cookie，浏览器关闭即丢失。
- access_token max_age = settings.access_token_expire_minutes * 60
- refresh_token max_age = settings.refresh_token_expire_days * 86400
- 前端刷新页面后通过 /auth/me 校验 Cookie 是否仍然有效，失败时调用 clearSession() 清理 localStorage.userId，避免"显示已登录但实际 Cookie 已过期"的状态错位。
- 切勿把 access_token 暴露给 JS（httponly=True），也不要在前端 localStorage 里保存 token 字符串。
- admin_token 是独立 Cookie（T2-2），与 access_token 隔离，管理员鉴权不依赖用户登录态。

3.7. 用户操作必须落日志
所有写操作（登录、发帖、评论、点赞、收藏、举报、资料修改）成功后必须调用 log_user_action() 记录审计日志。
- log_user_action 同时写 loguru 文件日志（logs/app.log，立即落盘）和 operation_logs 表（同事务提交）。
- 日志失败绝不阻断主业务流程（catch 后 logger.warning）。
- 排查用户错误时优先看 logs/app.log（按时间倒序），其次调用 GET /admin/user-logs?user_id=X&action=Y 过滤查询。
- action 命名规范：动词_对象，如 create_post / delete_comment / like / favorite / login / login_failed / register / logout / update_profile / report。
- 管理员操作必须写 admin_id（T7-6），便于追溯。

4. AI 只能从后端统一调用
前端不得直接调用任何 AI 接口。业务代码也不得绕过 app/services/ai_service.py。以后换 DeepSeek、通义千问或其他 OpenAI 兼容模型，只改 .env，不改业务接口。

5. AI 故障不能拖垮网站
AI 调用失败时，除审核相关能力外，其他系统功能必须正常。当前 ai_service 实现：
- 没有 OPENAI_API_KEY 时直接返回空结果，发帖审核默认放行。
- 网络异常 2 秒超时（T7-1）。
- 5 分钟熔断器：失败一次后 5 分钟内跳过所有 AI 调用（T8-1），避免反复重试阻塞。
- get_status() 返回 {available, reason}，前端通过 AiAuditCard 显示降级提示。
- 生产如需更严格策略，应只改 ai_service，不要散落到各业务接口。

6. 图片不进数据库
数据库只保存图片 URL。真正上传、压缩、格式限制、MinIO 存储应放在独立上传模块里，后续不要把图片二进制塞进 users/posts/images 表。
- 上传时校验 magic bytes（T7-10），防伪装 content_type 上传可执行文件。
- 发帖时校验 image_urls 是合法 HttpUrl（T7-11），拒绝 javascript: 等 XSS URL。

7. 当前验证码是开发 stub
send_code 和注册/登录里的验证码目前固定为 123456，只为本地联调。生产必须换成短信服务 + Redis 60 秒冷却 + IP/设备限制。

8. Alembic 是必做的迁移工具（T3-1 已完成）
V1 已引入 Alembic，废弃 Base.metadata.create_all。启动 .bat 脚本会自动执行 alembic upgrade head。
- 首次部署：alembic upgrade head 创建全部表。
- 升级部署：自动增量迁移到最新 schema。
- 禁止删除 alembic/ 目录或回退到 create_all。
- 新增字段/索引必须 alembic revision --autogenerate 生成迁移文件，不要手工 ALTER 表。

9. 安全能力已基本补齐（T2/T7 阶段）

仍需补齐（生产前）：HTTPS、CSRF 防护、Redis 替代 SQLite 持久化限流（多 worker 场景）。

不要再加营销落地页。这个项目面向校内使用，打开后应该直接进入社区界面、登录弹窗和帖子流。

12. 测试按接口逐步补齐

13. 为什么直接点 frontend/index.html 会空白
frontend/index.html 是 Vite 源码入口，不是普通静态网页。它依赖开发服务器把 Vue、TypeScript、Element Plus、Pinia 等源码编译后再交给浏览器。双击 HTML 会走 file://，浏览器无法正确解析 /src/main.ts、.vue 文件和 npm 依赖，Chrome 还会阻止 file:// 下的 ES Module/CSS 资源加载。正确方式是双击根目录"启动立洋社区.bat"，或在 frontend 目录执行 npm run dev 后访问 http://127.0.0.1:5173/。

14. dist/index.html 也不是正式部署方式
dist 是生产构建产物，应该由 Nginx、Vite preview 或其他 HTTP 服务托管。现代前端打包产物仍会使用 JS/CSS 资源，直接 file:// 打开不等同于线上部署。

15. 评论计数必须用后端绝对值，不能用前端 delta（T9-1 Bug 修复）
- 之前用 count-changed(delta) 手动 +1/-1，删除根评论时子回复未计入，导致 0 个评论却显示 1 个。
- 现在统一用 count-updated(total) 事件，后端返回 post_comment_count 绝对值，前端直接覆盖。
- delete_comment 删除根评论时级联删除所有子回复，重新统计 comment_count，保证数据库与列表一致。

16. 发布帖子后必须重置页码 + 滚动到顶部（T9-1 Bug 修复）
- 之前未重置页码，用户若在第 2 页发布，loadPosts 仍加载第 2 页，看不到新帖。
- 现在 PostEditor.publish 中 postStore.setPage(1) + CommunityHome.onPostPublished 滚动到顶部。

17. 路由参数变化时组件不会自动重新加载（T9-1 Bug 修复）
- Vue Router 在同一路由组件复用场景下（如 /search?q=a -> /search?q=b），onMounted 不会重新触发。
- 必须用 watch(() => route.query, ...) 监听参数变化重新加载数据。
- Search.vue 已修复，其他类似页面（如带 query 参数的列表页）也要注意。
